# Codex Updater 桌面端调整方案与交付说明

版本：设计评审稿 v1.1 · 2026-11-10

## 交付范围

`index.html` 是独立的高保真交互原型，包含内嵌样式、SVG 图标与 JavaScript。直接用 Edge 或 Chrome 打开即可，无需安装依赖、联网或运行项目。

本次交付用于公司内部设计评审和开发对照。正式 Electron 应用、PowerShell 脚本和安装器没有修改；原型不执行真实安装、修复、删除或迁移。版本号、空间占用和进度为示例。主题与偏好保存在当前浏览器，业务状态在重新打开后重置；底部“重置演示”同时恢复偏好。

浏览器禁止本地存储时，设置仍在本次会话内生效，并显示保存限制。窗口最小化和关闭使用可恢复的演示遮罩；最大化借用浏览器全屏。它们不是 Electron 窗口控制的实现。

## 已确认的设计决定

1. 左上角保留 mac 风格红黄绿装饰圆点，不可点击、不进入键盘焦点顺序。
2. 最小化、最大化／还原、关闭放在最右侧，保留独立的点击区，不与圆点重叠。
3. 移除标题栏右侧的已安装版本号；更新器自身版本只放在“设置 → 关于”。原型标记不进入正式产品。
4. “修复资源”是诊断页常驻主操作。环境显示正常时仍可手动修复，不能仅在异常时才出现。
5. 安装包缓存位置、Codex 本体安装卷、用户数据与项目目录分开说明。支持将缓存迁到 D 盘；应用迁移必须先检测 Windows 和包的支持情况。
6. 保留现有蓝色主色、灰色侧栏和白色卡片体系，调整信息层级与交互，不整体更换产品风格。

## 页面结构

### 概览

- 主卡片：当前更新结论、当前版本与可用版本、一个主要动作。
- 状态驱动按钮：下载更新 → 校验 → 安装并重启 → 更新完成；检查失败时变为重试检查。
- 次级信息：安装位置、安装包缓存、自动检查频率。
- 运行环境：5 项资源摘要；异常时有明确的诊断入口。
- 最近活动：只展示最近 3 条；全部记录放到弹窗。
- 避免把“尚未检查”表现成“已是最新”。成功结论必须有检查结果依据。

### 诊断

- 顶部提供“检查环境”，独立卡片常驻“修复资源”。
- 修复范围明确：Windows / WSL 命令行、搜索工具、Node.js 的运行资源副本。不是重置用户配置或万能修复。
- 修复确认提示保存工作、可能关闭 Codex；执行中阻止重复操作；结束后重新读取真实资源状态。
- 启动资源完整与主窗口能否启动分开表达，不把“5 项正常”等同于“所有功能正常”。
- 保留网络检测、启动测试和复制诊断摘要。
- 正式接入需沿用原有 `repair_bundles` / `runRepair` 能力和修复后的自检，不能替换成前端假成功。

### 版本与缓存

- 显示数量、总占用、最近同步时间、手动刷新。
- 同一版本行可重装／回退、保留、删除。
- 批量清理跳过已保留版本；显式删除保留版本时提示影响。
- 清理／删除确认包含数量、空间、影响；默认焦点放取消。
- 空缓存：显示“暂无安装包缓存”，说明已安装 Codex 不受影响。
- 读取失败：显示“无法读取缓存目录”，隐藏旧的可操作列表，提供重试。
- 安装前重新确认包仍存在、可读、签名有效，处理“列表读取后文件又被删”的情况。

### 设置

| 分类 | 内容 |
| --- | --- |
| 通用 | 自动检查、频率、通知、关闭后托盘、开机启动 |
| 外观 | 浅色、深色、跟随系统；主题预览；减少动态效果跟随系统 |
| 存储 | 磁盘空间、应用本体位置、迁移条件检测、缓存位置与已有缓存迁移、清理策略 |
| 关于 | 更新器版本、来源说明、非官方工具说明、帮助 |

## 状态与行为规范

### 主题

主题偏好取值为 `light / dark / system`。渲染主题由偏好和系统主题共同解析。显式浅色／深色必须优先于系统；只有 system 才跟随系统变化。

原型通过 `data-theme`、CSS 变量、`matchMedia` 和 `localStorage` 演示。正式桌面端应继续使用主进程持久化，并同步 `nativeTheme.themeSource`。不要把原型的 localStorage 当作生产设置的第二个来源。

主题切换需要覆盖标题栏、侧栏、卡片、表单、弹窗、提示、滚动条。启动读取设置前使用已保存的主题信息，避免闪白。快速连续切换应按最新请求生效，防止异步回读乱序。

### 缓存同步

统一维护 `directory / items / totalBytes / status / refreshedAt / error`，概览、导航数量、版本列表、设置都读取同一份快照。

刷新触发条件：应用启动、进入相关页、窗口激活、下载或删除完成、目录切换、目录变化通知。建议主进程监听当前有效下载目录，按 300–500 ms 防抖重新扫描；焦点刷新作为补偿，不能只依赖监听器。

目录切换时注销旧监听器并用代次标记丢弃过期扫描结果。目录不存在、拒绝访问、空目录要区分。空目录的数量与大小归零；读取失败显示未知／失败，不让旧列表继续用于安装。当前下载或安装锁定的文件不能被清理／迁移。

原型用独立的“模拟磁盘”和“界面快照”演示上述同步；“模拟外部删除缓存”先清空模拟磁盘，再通过事件防抖刷新。浏览器不能据此监听真实文件系统。

### 更新与安装

`待检查 → 检查中 → 可更新 → 下载中 → 校验中 → 待安装 → 安装中 → 完成`。

取消下载回到可下载状态；网络失败显示重试；签名失败阻止安装；取消管理员授权回到待安装并保留包。安装和修复等互斥操作禁用冲突入口。正式安装过程不能伪造百分比，无法获取进度时使用阶段状态。

含 Windows 服务的安装包可能需要管理员权限。手动桌面流程按现有单次授权机制执行；无人值守维护继续遵守现有不弹 UAC 的规则。原型不改变自动维护行为。

### 窗口和无障碍

右侧按钮从左到右为最小化、最大化／还原、关闭。最大化图标以主进程窗口状态为准；双击标题栏也必须同步状态。按钮区禁止拖动、禁止双击冒泡触发最大化。左侧装饰圆点不包含可操作角色。

关闭行为服从托盘偏好；安装／迁移期间关闭必须有明确处理策略，不能直接终止后台任务。原型用提示阻止关闭进行中的更新。

支持 Tab 焦点、主题单选方向键、设置标签方向键、ESC 关闭弹窗。弹窗使用原生 dialog 约束焦点；toast 使用礼貌播报。颜色之外同时用文字表达状态，尊重系统减少动态效果设置。

## D 盘与空间管理方案

### 安装包缓存：可以独立支持

“更改目录”只改变后续下载位置，不删除或搬动旧目录。切换后重新扫描新目录，并告知旧文件仍在原处。

“迁移已有缓存”流程：选目标目录 → 校验可写和可用空间 → 展示数量／大小及源目标 → 确认 → 复制 → 完整性校验 → 原子切换设置与监听器 → 清理已验证的源文件 → 刷新。保留标记和版本元数据一并迁移。

失败保留源文件与原设置；同名文件先校验，不能直接覆盖；路径需规范化并防止源目标相同或嵌套。旧文件清理失败时提示“迁移完成，原目录尚有文件”，不能虚报释放空间。

原型以 `D:\CodexPackages` 演示目标目录，实际实现使用系统目录选择器。此演示路径不应写入自动化模板。

### 应用本体：Windows 支持有条件迁移

Windows 官方文档确认：

- `Move-AppxPackage` 可以将包移动到另一个已被包管理器识别且已挂载的 AppxVolume，也会迁移受其管理的应用数据。
- `Add-AppxPackage -Volume` 支持指定暂存／安装所使用的 AppxVolume。

因此不能笼统说“官方 MSIX 永远不能放到 D 盘”，也不能仅凭存在这两个命令就承诺当前 Codex 包一定能迁移。

开发前检测：包身份、版本、包的移动限制、系统策略、目标卷是否受支持并在线、可用空间、部署状态、依赖／服务约束和权限。目标是 Windows 应用卷，不是任意自定义应用目录。

建议先提供能力检查和 Windows 应用管理入口，再接入受支持的包迁移。未安装时显示“设为安装磁盘”；已安装时显示“迁移到 D 盘”。检测不支持时显示具体原因并保留缓存迁移入口。

执行时记录原包位置并关闭 Codex，通过 Windows 包部署服务迁移，不使用文件复制、目录联接或取得 WindowsApps 所有权的方式搬动。完成后重新获取 `InstallLocation`、验证包状态、运行修复所需的路径解析和启动测试。失败按包部署的实际状态提供恢复措施，不声称一定已经自动恢复。

迁移成功后，更新、修复、启动、版本回退都必须继续识别实际位置，不能下一次更新又默认回 C 盘。依赖包和系统暂存区仍可能占用 C 盘，需要展示真实空间需求。

2026-11-10 对用户本机做过只读检查：当前包安装在 C 盘，C / D 为 NTFS；当前清单未显示显式移动限制并不等于已经验证迁移可行。本次没有移动真实应用、注册应用卷或变更系统设置。

### 用户数据：单独说明

Windows 受包管理的数据与 Codex 写到外部用户目录的数据不是一回事。本机清单存在文件系统虚拟化排除目录。因此迁移应用不能承诺把配置、日志、会话、缓存和代码目录全部移走。

本期不设计一个未经验证的“迁移全部用户数据”按钮。展示占用分类与真实路径；只有在官方支持、路径依赖与恢复方案确认后，才增加相应迁移能力。

## 文案调整

| 原表达 | 新表达 | 用意 |
| --- | --- | --- |
| Installed / 已安装 版本号 | 发现新版本 / 已是最新 | 标题先表达当前结论，版本在固定位置展示 |
| 一键检查并更新 | 下载更新 → 安装并重启 Codex | 分清不影响工作和会关闭应用的步骤 |
| 启动所需资源完整 | 运行环境正常 | 概览简短；诊断页再说明检测范围 |
| 只认本机缓存 | 回退需要本机安装包 | 清楚说明约束 |
| 照样校验签名 | 安装前校验签名 | 统一正式表达 |
| 旧包在磁盘上可能躺了几周 | 安装前重新校验签名 | 去掉口语化论述 |
| 缓存占用未知 | 正在扫描 / 无法读取缓存目录 | 以真实原因区分状态 |
| 还有没有记录……这里会列出结果 | 暂无活动 | 空状态只说明现状和下一步 |
| 所有改动立即生效 | 更改自动保存 | 具体效果由对应设置说明，避免一概承诺 |
| 由 Windows 决定，只读 | 检测迁移条件 | 有条件开放，而非简单禁止 |

规则：按钮使用动词；每项设置最多一行目的说明；长解释放详情和确认框；风险说明在操作前出现；非官方说明集中在关于和帮助，不在每个区域反复堆叠。

## 实施顺序与代码落点

1. `desktop/src/components/TitleBar.tsx`、`desktop/src/styles.css`：先修左右布局、拖动区、最大化同步，再对真实安装包做回归。
2. `AppearanceSettings.tsx`、`state/app.ts`、`electron/main.cjs`：核对保存／回读／应用主题链路，增加显式主题映射与失败反馈。
3. `state/app.ts`、`electron/main.cjs`、`electron/preload.cjs`：建立缓存刷新事件和统一快照，替换静默失败。
4. `HealthPanel.tsx`：保留真实修复动作，提升常驻入口，明确任务互斥与修复后自检。
5. `CacheSettings.tsx`、`VersionHistory.tsx`、`AdvancedSettings.tsx`：接入存储分组、缓存迁移、应用卷能力检测。
6. 应用本体迁移独立实现与验证，不和视觉调整绑定成一个必须同步上线的大改动。

原则：保持现有后端能力（KISS）；页面共用设置、缓存和任务状态（DRY）；原型与真实命令桥接分离，迁移检查与执行分离（单一职责）；未经验证的用户数据搬迁不预留虚假可用入口（YAGNI）。

## 原型评审路线

1. 概览下载更新，取消后重试，下载完成后查看安装确认，再演示完成。
2. 诊断在正常状态点击修复；切换“资源异常”场景再执行修复，查看侧栏与结果同步。
3. 设置 → 外观切换三种主题，刷新确认偏好保存；跟随系统时改变系统配色。
4. 版本与缓存点击“模拟外部删除缓存”，查看列表、侧栏数量、首页空间同步归零。
5. 清理缓存先取消，再确认；核对被保留的版本仍存在。
6. 设置 → 存储迁移已有缓存，再检测迁移条件、演示应用迁到 D 盘。
7. 底部切换缓存读取失败、签名失败、取消授权、不支持迁移，验证失败反馈。

## 上线前验收要求

- [ ] 使用实际打包 EXE 验证标题栏在 100% / 125% / 150% 缩放下不会重叠；双击、拖动、最大化还原正确。
- [ ] 实际设置落盘后重启仍保留主题；系统变化仅影响“跟随系统”；失败时不显示保存成功。
- [ ] 资源管理器删除文件、删除目录、改权限、切换目录、切回窗口时，缓存快照与按钮状态正确。
- [ ] 正常状态可以手动修复；修复失败能重试并查看日志；完成后结果来自真实自检。
- [ ] 安装、回退、修复、缓存迁移、应用迁移互斥；安装前存在性与签名再次检查。
- [ ] 缓存迁移处理空间不足、权限失败、重复文件、用户取消、中断恢复，不丢失源文件。
- [ ] 在允许和禁止移动的实际 MSIX 上分别验证；迁移后升级、修复、启动、回退全部识别 D 盘位置。
- [ ] 检查 Windows 服务包的 UAC、取消授权与失败恢复；无人值守保持不弹 UAC。
- [ ] 真实磁盘空间由后端读取，容量预检考虑临时空间，不使用原型示例值。
- [ ] 原型工具条、示例版本和假数据不进入正式发行包。
